## 本地采集验证摘要

- 已为选定文稿保存 V1，原文件保持不变；认可状态为 pending，没有代替使用者确认。
- 定向采集只读取显式绑定的会话 JSONL 路径，核对其 `session_meta.id` 和 `cwd`。
- 实测完整保存超过 1 MB 的原始来源和完整行游标，没有截断。
- 首次状态为 `caught_up`、`live_status=armed`、`completed=false`，正确表示建立基线且本轮尚未结束，未把历史会话硬配给当前文稿。
- 验收时真实正式经验数为 0。演示候选与测试审核均隔离在演示目录或临时测试目录。
- 公开代码仓库不包含文稿资产仓库、会话原始记录、实际任务与会话绑定、密钥或生成的演示输出。本地初次开发记录仍保存在原开发历史中。

## 外部接入还需要什么

1. 团队认可的私有 GitHub 仓库地址，以及已登录且有访问权限的 `gh`。在实际 PR 中由另一位团队成员审核、合并后验证发布和撤销。
2. 团队指定 Langfuse 项目，在本机设置 `LANGFUSE_HOST/PUBLIC_KEY/SECRET_KEY`。密钥不写入代码或聊天。验证长内容读回、断网恢复、评分和提示词版本。
3. 已提供项目 [.codex/hooks.json](../.codex/hooks.json) 与 [绑定配置模板](../hooks/writing-memory-hook.example.json)，使用者需填入自己的选定文稿和会话。Codex 要求用户信任新增 Hook 定义；没有改写信任记录或使用绕过选项。初次验收环境的 CLI 二进制缺失，桌面实际加载、信任和 Stop 调度仍待验证。[官方 Hook 信任说明](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks)
4. 用一份真实文稿完成修改、人工确认、在下一次写作使用与反馈，才算方案定义的完整业务闭环。

## 复验方法

初次验收执行全套 **79 项自动化测试，全部通过**（77.543 秒）。已构建 wheel 包，并在脱离源码目录的临时环境验证创建任务与读取包内提示词；实际适配器进程手动调用成功（0.92 秒），超过 1 MB 的会话快照仍正确标为本轮未完成；文稿内容和 V1 数量再次核对无变化。手动执行适配器不等于桌面自动触发通过。

```sh
python3 -m unittest discover -s tests -v
uv build --wheel
python3 examples/run_local_demo.py --output demo-output
python3 -m writing_memory init
python3 -m writing_memory doctor
python3 -m writing_memory status
python3 -m writing_memory recover
```

演示命令在尚不存在的 `demo-output/` 目录生成文稿、V1→V5、候选和 `演示结果.md`。目录已存在时请另选新路径。演示内容为离线样例，不代表真实人工审核或发布。

## 本轮发现并修复

1. **未采用草稿会影响当前稿的风险**：原存储把最后版本当作当前稿。新增独立草稿，只有采用才进入正式版本序列。
2. **保存了历史却未读取**：旧改稿调用未使用历史要求与个人批准经验。新网页组装有效要求和匹配规则，保存实际调用快照。
3. **正文末尾没有换行时差异黏行**：标准 diff 生成器保留原文末尾状态，直接拼接会让删除/新增行连在一起。补充独立换行与缺失换行标记，原文不变，并加入回归用例。
4. **采用中断后的不确定性**：把写回意图、采用来源和待提炼事件与版本一起落盘，再受哈希保护地写回；重复采用不生成重复版本。
5. **个人确认冒充团队批准的风险**：个人规则单独保存 authority 和修订，不进入 GitHub releases。
6. **模型建议范围过宽**：本地候选默认约束为来源材料的文种和读者；更广范围必须由用户明确选择。

## 当前边界

- macOS 优先、TXT/Markdown；不直接编辑 Word/PDF，不提供多人登录和公网托管。
- 冲突提示基于适用范围重叠，不能识别所有语义矛盾；需人工核对。
- 上下文采用保守 UTF-8 字节预算，不是精确 token 计数；超出则停止调用，不静默截断原始要求。
- 已发送的请求不能在网页中强制取消；排队请求可取消。退出服务会等待已发出的请求保存结果；被强制终止后需显式重试，可能再次计费。
- 旧 GitHub 团队审核、Langfuse 与桌面 Hook 仍属于进阶流程；本次没有替团队进行真实审核或对外同步。
- Linux/Python 多版本检查由 GitHub Actions 提供；Windows 原生依赖 fcntl 限制，本版不支持。

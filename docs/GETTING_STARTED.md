# 六课新手教程：让 AI 从真实改稿中积累写作经验

目标不是记住所有技术名词，而是完成一个可验证的练习：改第一篇材料，确认一个偏好，再看第二篇材料是否真正使用了它。

每课按「理解 → 操作 → 看结果 → 排查」进行。先使用文中的虚构内容，不要拿测试结果当成真实业务事实。

## 第一课：谁在写，谁在记，谁在学习

把系统想成一个写作小组：

- **DeepSeek** 是执笔者，根据收到的上下文写内容。
- **Agent** 是能够围绕模型组织工作和工具调用的程序。
- **Harness** 是 Agent 的运行环境，决定给模型哪些规则、工具、记忆。
- **RSIH** 是本项目使用的 Harness 引擎，基于 Pi。
- **Genome** 是放在文件夹中的工作说明书，描述提示词、模型、技能、策略等配置。
- **知稿工作台** 管理文稿和修改记录，将你确认的偏好放进本次派生 Genome。

这里的 RSI 是改进 Agent 的工作配置，不是让 DeepSeek 修改自己的模型参数。模型不会因为你在某次调用里说“记住”就永久记住；工作台必须把规则保存下来，并在下次调用时提供给它。

**三个检查点：**「记录保存了」看版本和原始指令；「规则加载了」看实际调用快照；「效果变好了」看新稿是否遵守要求。前两个通过，不保证第三个永远通过。

文件夹的详细地图见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 第二课：安装一次，以后打开就用

### 2.1 准备工具

Mac 按 `Command + 空格`，搜索“终端”。逐条执行，不要在上一条还没有结束时粘贴下一条：

```sh
git --version
python3 --version
node --version
npm --version
```

需要 Git、Python 3.10 或以上、Node 22.19 或以上以及 npm。

- Git 不存在：执行 `xcode-select --install`，在系统窗口完成安装。
- Python 不存在或太旧：从 [Python 官网](https://www.python.org/downloads/) 安装。
- Node/npm 不存在或太旧：从 [Node 官网](https://nodejs.org/) 安装符合要求的 LTS 版本。
- 创建自己的 [DeepSeek API Key](https://platform.deepseek.com/)，确认 API 账户有额度。DeepSeek 网页会员不等于 API 额度。

安装工具后重开终端再检查。不要把密钥粘贴成终端命令，也不要发到仓库或群聊。

### 2.2 下载工作台

```sh
git clone https://github.com/chutian1819/RSI-Harness.git ~/writing-workbench
cd ~/writing-workbench
./scripts/install-macos.sh
```

安装器会检查工具、下载固定版本 RSIH 引擎、创建 `.venv`、安装工作台并做基础配置。首次需要下载依赖，可能持续几分钟。`.venv` 是这个项目自己的 Python 工具箱。

引擎和依赖保存在 `~/.local/share/rsih-writing-runtime/`。没有 Bun 时会使用 Node 启动方式，不影响基础使用；请保留运行目录。

如果目标目录已经存在，请进入已有目录，不要删除自己的材料。安装失败时先处理屏幕上第一条错误，再重试；脚本不会覆盖已有密钥和基础 Genome。

### 2.3 配置自己的密钥

```sh
.venv/bin/writing-memory-rsih setup
.venv/bin/writing-memory-rsih doctor
```

按提示粘贴密钥并回车。输入时不显示字符或星号是正常行为。`doctor` 返回 `ready: true` 表示本地依赖和文件齐备；它不联网，不代表余额或 API 已通过验证。

暂时没有密钥可以跳过这一步，仍可新建、编辑和查看材料；生成与提炼需要密钥。

默认使用 `deepseek-flash`。需要更换支持的模型时，例如：

```sh
.venv/bin/writing-memory-rsih setup --model-id deepseek-v4-pro
```

更换密钥用 `setup --replace-key`。不要手工把密钥填进代码。

### 2.4 打开网页

```sh
.venv/bin/writing-memory-rsih web
```

浏览器自动打开。如果没有打开，复制终端显示的**完整地址**到浏览器，其中包含本次本机连接凭据。网页地址是 `127.0.0.1`，表示你的电脑，不是公共服务器。

终端需要保持运行。退出按 `Ctrl+C`；已发送的调用会先保存结果。下次在项目目录执行同一条 `web` 命令即可继续，不需要一直开着 Codex。

端口被其他程序占用时：

```sh
.venv/bin/writing-memory-rsih web --port 8766
```

同一个数据目录只能启动一个网页服务，避免多个服务互相判断对方的任务“已中断”。

### 不使用安装脚本的手动步骤

如果希望理解每一步，可以手动安装。不要与自动安装同时执行。

```sh
cd ~
git clone https://github.com/CosmosMind-ai/RSI-Harness.git rsih-engine
cd ~/rsih-engine
git checkout 33c4f8dfac4359987f2e814e187de67c332498de
./install.sh --copy
```

这是固定引擎版本，出现 `detached HEAD` 是正常提示。没有 Bun 时可能回退到依赖此源码目录的启动方式，因此保留 `~/rsih-engine`。

```sh
cd ~/writing-workbench
python3 -m venv .venv
.venv/bin/python -m pip install -c requirements.lock .
.venv/bin/writing-memory-rsih setup --rsih ~/.local/bin/rsih
.venv/bin/writing-memory-rsih web
```

最后的引擎路径以安装器实际输出为准。

## 第三课：完成第一次改稿

### 3.1 建档

首页点击「用虚构材料练习」，表单会填入一份虚构经营分析。查看文种「经营分析」、读者「部门负责人」，然后点击创建。

也可以「新建材料」，粘贴原稿或导入 UTF-8 `.txt` / `.md`。留空表示先建一个空白档案，随后让 AI 起草。新建不调用模型。

**为什么要写文种和读者？** “给领导看的经营分析”与“给员工看的讲话稿”写法不同。偏好按这些字段匹配；建议团队约定固定名称，避免「部门负责人」与「领导」混用而不匹配。

### 3.2 提要求

在本轮修改要求中输入：

```text
摘要和经营数据部分重复较多。请把摘要改成一句总体判断，具体数据留在正文。不新增未经提供的原因和成果。输出完整修改稿。
```

点击生成。此时会真实调用付费 API。页面显示排队或处理中，返回完整结果后展示草稿，不承诺逐字流式显示。

「采用后，本篇后续修改继续遵循这条要求」默认勾选。如果只是这次的临时格式要求，取消勾选。

### 3.3 比较并采用

右侧展示增删差异，也可展开完整草稿。核对原有数据是否保留、是否编造内容。

在右上角填写你的确认人姓名，然后选择「采用这一稿」或「不采用」。采用才生成正式新版本；不采用仍保留该草稿及指令，当前稿不变。

**常见误解：** AI 返回文本不等于已经保存为正式稿。将“生成”和“采用”拆开，防止不满意的结果悄悄覆盖原稿。

采用后自动提炼会额外调用一次模型。正文已经落盘，提炼失败不会撤销这一稿。

## 第四课：看懂版本，理解恢复

进入「版本与原始指令」：

1. 找到 V1 原稿与 V2 修改稿。
2. 查看原始修改要求，而不是 AI 对你的话的转述。
3. 查看草稿的前后差异与本轮上下文。
4. 选择旧稿的「以此稿生成新版本」，会得到 V3，而不是把 V2 删除。

你也可以直接编辑左侧正文，填写修改说明后保存。手工保存同样形成正式版本，并提炼候选。未保存输入有离开提示。

**为什么恢复还要增加一个版本？** 因为“回到旧稿”也是一次真实操作。如果直接覆盖历史，后面就无法解释曾经发生过什么。

若生成期间另一处更新了正文，旧草稿会标为基于旧版，不能直接采用。这样可以防止你刚保存的新内容被较早的模型请求覆盖。

## 第五课：让记忆生效，再验证它

### 5.1 看候选，不急着确认

进入「写作记忆」。候选可能是“经营分析摘要只写总体判断，数据放在正文”。点击查看依据，核对：

- 原始指令是否真有这个意思？
- 修改前后文是否支持这个总结？
- 它是长期写法，还是这篇材料的一次性要求？
- 默认文种与读者范围是否准确？

可以编辑文字和范围、暂缓、不采纳或确认。事实纠错、一次性需求不会直接确认为个人长期偏好。所有范围都改为 `*` 才是你主动选择的通用规则。

候选为零条是正常结果，可能因为证据不足。不要为了看到“记住了”强行提炼。

### 5.2 处理重叠规则

同一范围已经有规则时，页面会列出供你核对。它们是**潜在冲突**，不代表程序能准确判断所有语义矛盾。

你可以缩小范围、勾选替换旧规则，或者确认两条可以共存。替换与撤销都有修订记录。若保留了真正矛盾的规则，模型仍可能表现不稳定，应调整规则。

### 5.3 做第二篇实验

新建另一份材料，仍选择「经营分析」和「部门负责人」。不要重复强调摘要的写法。

1. 在「本篇要求与记忆」确认规则匹配。
2. 生成草稿，在调用记录中确认实际加载了该规则及修订号。
3. 检查正文是否遵守规则。
4. 换成其他文种或读者，检查该规则不会误用。
5. 撤销规则，再发起新请求，确认不再加载。

这才是完整的学习验证。已确认规则不会自动改写已经生成的稿件；它只影响后续请求。排队期间规则被撤销的旧请求会停止，要求重新提交。

**完整存档不等于每次发送全部旧稿。** 生成时发送当前正文、有效历史要求和匹配规则；所有旧稿仍在档案里。提炼分析指定已采用轮次的完整前后文。历史要求不静默截断，超过保守预算时会报错并保留记录。

## 第六课：理解 RSI，分享可复用经验

你的循环是：有证据的修改 → 候选 → 人确认 → 生成本次派生 Genome → 新稿应用 → 检查效果 → 再调整。

基础 Genome 保存通用写作要求；已确认偏好保存于个人规则库。每次调用复制基础 Genome，加入匹配规则并校验，形成独立快照，因此不会覆盖你自己编辑的基础配置。

原版命令的含义：

```sh
rsih                  # 原版 Agent 入口，不是知稿网页
rsih genome list      # 看可用 Genome
rsih genome show 名称 # 查看解析后的配置
gee                   # 根据选定历史辅助生成 Genome 的交互入口
```

自动安装的引擎不一定加入全局 PATH。若提示找不到 `rsih`，使用 `runtime.json` 中记录的可执行文件完整路径。`gee` 不是后台训练程序，也不会自动捕获所有聊天软件里的对话。

### 分享规则

在「已经确认」中选中规则 → 分享 → 检查预览 → 按需改掉业务专有信息 → 下载规则包。同事在自己的工作台导入，逐条确认后才生效。

只分享规则包或 GitHub 代码链接，不要分享整个数据目录。分享包采用字段白名单，不附原稿、来源全文、调用日志或密钥，但无法替你判断规则文字里所有业务信息是否适合公开。

个人确认不等于团队审核。原有 GitHub 团队审核流程保留为进阶模块，见 [CLI.md](CLI.md)。

## 日常备忘

每天通常只需：

```sh
cd ~/writing-workbench
.venv/bin/writing-memory-rsih web
```

更新代码：关闭服务，确认自己没有待处理的代码修改，执行 `git pull --ff-only`，再运行 `.venv/bin/python -m pip install -c requirements.lock .`。个人数据目录不在代码目录里。

备份：关闭工作台后，把整个 `~/.local/share/rsih-writing-lab/` 复制到自己的受控备份位置。里面有密钥和材料，不适合公开共享。Git 历史不是异地备份。

## 常见问题：从现象找到原因

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `command not found` | 工具没安装，或不在 PATH | 检查第二课工具；日常命令使用完整 `.venv/bin/...` |
| 密钥输入看不到字 | 隐藏输入 | 粘贴后回车，不是死机 |
| doctor 通过但生成失败 | doctor 不联网 | 看任务错误，检查密钥、额度、网络 |
| 401 | 密钥失效或不正确 | `setup --replace-key` |
| 超时、余额不足、限流 | 服务请求未成功完成 | 正文不变；恢复后显式重试，可能再次计费 |
| 返回截断或空正文 | 模型未正常完成输出 | 不保存成草稿；拆分材料或核实输出上限 |
| 上下文预算超限 | 当前正文、要求、规则合计太长 | 拆分材料，停用不再适用的历史要求；原始记录不删。核实模型容量后才调整 `writing-settings.json` 的 `max_context_bytes` |
| 基于旧版，不能采用 | 生成期间正文已经变化 | 基于当前稿重新提出要求，不覆盖新稿 |
| 页面提示外部修改 | 用其他编辑器改了 `current.md` | 先备份，再用旧 `record` 入口登记，见 [RSIH.md](RSIH.md) |
| 草稿采用成功但提炼失败 | 两个独立操作，第二个失败 | 正式稿保留，在任务区重试提炼 |
| 规则没有匹配 | 文种、读者、主题使用不同名称 | 核对范围，匹配采用精确名称或 `*` |
| 网页显示连接凭据失效 | 服务已重启，旧标签页令牌失效 | 从终端最新完整地址重新打开 |
| 服务关闭，网页还能看但不能操作 | 浏览器内容还在，后端已停止 | 重新执行 `web`，打开新地址 |
| 数据似乎不在旧高级 CLI 中 | 两个入口默认数据根不同 | 工作台根是 `~/.local/share/rsih-writing-lab/manuscript-assets`；高级 CLI 使用它时显式传 `--root` |

排查时提供错误文字，不要公开密钥文件或整份模型日志。更多实现与验证边界见 [工程说明](ENGINEERING.md) 和 [验收记录](ACCEPTANCE.md)。

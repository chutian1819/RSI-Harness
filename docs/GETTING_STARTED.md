# 新手操作手册：从安装到第一次改材料

你最终会得到一个终端菜单和一个本地查看网页。终端用来输入材料、提出修改意见；网页用来看每一版内容、修改差异和候选写作经验。

先用本文的虚构材料练习，再放入适合发送给 DeepSeek 的真实工作材料。每次“修改”和“提炼”都会调用你自己的付费模型接口；安装、建档、看记录不会调用模型。ChatGPT/DeepSeek 网页会员不等于 API 额度。

## 1. 准备工具（只做一次）

本教程面向 macOS/Linux；以下命令逐块复制到终端并回车。遇到报错先停在当前步骤，按文末排障，不要继续粘贴后续命令。命令运行结束、重新出现输入提示符后，才输入下一条。

Mac：按 Command + 空格，搜索“终端”。准备：

- **Git**：下载和保存代码。Mac 执行 `xcode-select --install` 可安装命令行工具（已安装会提示无需安装）。
- **Python 3.10 或以上**：运行本工作台。可从 [Python 官网](https://www.python.org/downloads/) 安装。
- **Node.js 22.19 或以上及 npm**：安装 RSIH 引擎。可从 [Node.js 官网](https://nodejs.org/) 安装符合要求的 LTS 版本。
- **DeepSeek API Key**：在 [DeepSeek 开放平台](https://platform.deepseek.com/) 创建，确认 API 账户有可用额度。每位同事使用自己的密钥，不要发进群聊或代码仓库。

Linux 请用发行版的包管理器安装 Git、Python 和 venv 支持，并按 Node 官网说明安装符合版本要求的 Node。Ubuntu/Debian 缺 venv 时可运行 `sudo apt install python3-venv`。

在终端检查：

```sh
git --version
python3 --version
node --version
npm --version
```

每条都应显示版本号。如果提示 `command not found`，先完成对应安装，并重开终端。

## 2. 安装 RSIH 引擎（只做一次）

引擎负责调用模型，工作台负责管理材料，两者分开安装。这里固定到本工作台使用过的上游版本，减少更新带来的接口变化。

```sh
cd ~
git clone https://github.com/CosmosMind-ai/RSI-Harness.git rsih-engine
cd ~/rsih-engine
git checkout 33c4f8dfac4359987f2e814e187de67c332498de
./install.sh --copy
```

安装需要下载依赖，可能持续几分钟。`detached HEAD` 是固定版本产生的正常提示。若没有安装 Bun，安装器会回退到 Node 启动方式，也可以使用；**请保留 `~/rsih-engine` 文件夹，不要移动或删除它**。

检查成功：

```sh
~/.local/bin/rsih --version
```

应输出版本号。若默认位置没有文件，查看安装器最后显示的路径，在下一步 `setup --rsih` 中使用那个路径。

## 3. 下载并安装写作工作台（只做一次）

```sh
cd ~
git clone https://github.com/chutian1819/RSI-Harness.git writing-workbench
cd ~/writing-workbench
python3 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/writing-memory-rsih --help
```

最后应看到 `setup`、`doctor`、`menu` 等命令。`.venv` 是这个项目自己的 Python 工具箱，避免与其他项目混用。本文始终写完整的 `.venv/bin/...`，不需要额外“激活环境”。

如果提示目标文件夹已存在，先确认是否之前已下载；已下载则直接 `cd` 进入，不要删除旧材料或重复克隆。

## 4. 配置自己的模型（只做一次）

```sh
cd ~/writing-workbench
.venv/bin/writing-memory-rsih setup --rsih ~/.local/bin/rsih
```

看到“请输入你自己的 DeepSeek API Key”后，粘贴密钥并回车。**输入时不显示字符或星号，这是正常的隐藏输入。** 不要把密钥当作命令输入。

配置成功会显示 `genome_valid: true`、`credential_ready: true`。程序会创建一份通用写作规则、模型连接配置，并把密钥只保存在你本机的私有数据目录。重复运行会保留已有密钥和 Genome；更换密钥时才用 `setup --replace-key`。

再检查：

```sh
.venv/bin/writing-memory-rsih doctor
```

看到 `ready: true` 表示本地文件和依赖齐全。它不联网，所以不代表密钥、余额或网络已经通过验证；第一次修改才会真实调用模型。

暂时没有密钥？可用 `setup --rsih ~/.local/bin/rsih --skip-key` 先配置本地功能，建档、看记录仍可用；此时 `doctor` 的 `ready: false` 属于预期，修改和提炼需补齐密钥。

## 5. 用虚构材料走完第一轮

启动：

```sh
.venv/bin/writing-memory-rsih menu
```

### 5.1 输入 1：新建材料

按提示填写：

| 提示 | 练习内容 |
| --- | --- |
| 名称 | 练习：九月经营分析（虚构） |
| 用途 | 月度汇报练习 |
| 读者 | 部门负责人 |
| 文种 | 经营分析 |
| 主题 | 业务经营 |

在输入初始材料的位置粘贴下面全文，最后一行的英文句号也一起粘贴，再回车：

```text
# 九月经营分析（虚构练习）

## 摘要
本月收入120万元，同比增长10%；服务客户300家，同比增长15%。

## 一、经营数据
本月收入120万元，同比增长10%；服务客户300家，同比增长15%。

## 二、下一步建议
建议进一步分析客户需求，具体措施待补充依据后确定。
.
```

此时保存了 V1 原稿，尚未调用模型。V1、V2 就像同一篇材料的第一版、第二版。

### 5.2 输入 2：请 AI 修改

选择刚创建的材料序号，输入以下指令（末尾句号另起一行）：

```text
这是虚构练习。摘要和第一部分经营数据重复较多。请把摘要改成简短的总体判断，具体数据留在第一部分，不新增未经提供的原因和成果。请输出修改后的完整材料。
.
```

程序显示操作编号并等待模型，期间会提示等待进度。成功后显示全文并保存 V2。正常响应可能需要几十秒；超过本次调用的等待上限会报错，原稿保留。

你还可以再次选择 2，提出“摘要再精简为一句话”等意见，形成 V3。这些练习反馈会如实记录为练习，不应拿来宣称真实业务用户已经认可效果。

### 5.3 输入 4：查看结果

Mac 会打开本地网页。Linux 请复制终端显示的 `manuscripts.html` 路径，用浏览器打开。网页显示：

- V1/V2 各自的完整内容。
- 你输入的修改意见。
- 前后差异：删了什么、增加了什么。
- 如果已经提炼，候选经验及其来源。

网页只是查看器；继续修改请回终端。生成新记录后重新选择 4 或刷新网页。

### 5.4 输入 3：提炼写作经验

选择材料，再等一次模型响应。这一步分析真实保存的指令和版本，尝试提出可复用经验。

**可能返回空列表 `[]`，这不是失败。** 模型可能认为练习、一次性指令或证据不足，不应形成长期习惯。不要为了得到“学会了”的显示而强行写入规则。

有候选时，选择 5 可输入候选编号和姓名，再选择：

| 输入 | 含义 |
| --- | --- |
| `defer` | 暂缓，等更多例子 |
| `reject` | 不采纳 |
| `review` | 准备团队审核材料，尚未发布 |

这三个动作都不会改写 Genome，也不会让下一篇材料自动使用候选。正式审核和复用参见 [团队流程](CLI.md#提炼审核与复用)。首次体验可以先停在查看候选，不必配置整套团队服务。

### 5.5 输入 0：退出

退出不会删除已保存的文稿。

## 6. 第二天怎么继续

以后通常只需两行：

```sh
cd ~/writing-workbench
.venv/bin/writing-memory-rsih menu
```

旧材料仍在列表里；新材料选 1，继续旧材料选 2。没有后台服务需要启动，也不必一直开着 Codex。

想直接查看记录：

```sh
.venv/bin/writing-memory-rsih view
```

该命令输出本地网页路径；在浏览器打开即可。Mac 也可从菜单 4 自动打开。

## 7. 文件在哪里、怎样备份

默认数据目录是 `~/.local/share/rsih-writing-lab`。`~` 表示你的个人主目录，点号开头的文件夹通常默认隐藏。Mac 可在 Finder 按 Command + Shift + G，粘贴这个路径进入。

| 文件或目录 | 通俗解释 |
| --- | --- |
| `credentials.json` | 密钥，只给自己用；文件权限限制为本人读写 |
| `runtime.json` | 引擎安装在哪里 |
| `agent/models.json` | 使用哪个模型、连接哪个接口；这里保存密钥变量名而非密钥 |
| `genomes/writing-demo/` | 当前写作说明书；初始内容是通用模板 |
| `manuscripts/doc_.../current.md` | 某篇材料的最新全文 |
| `manuscripts/doc_.../versions/` | 第一版、第二版等历史版本 |
| `manuscripts/doc_.../turns/` | 每轮修改意见和前后差异 |
| `manuscripts/doc_.../operations/` | 实际请求、回复和执行状态，便于定位失败原因 |
| `manuscript-assets/` | 文稿与候选的权威记录，带独立 Git 历史 |
| `manuscripts.html` | 展示记录的网页 |

关闭程序后备份整个数据目录，才能保留配置和完整历史；备份含密钥和文稿，应存到自己的受控位置。向同事分享程序只分享 GitHub 代码链接，不要把整个数据目录发给同事。Git 历史不是异地备份，电脑损坏仍可能丢失资料。

## 8. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 粘贴材料后看起来没有反应 | 多行输入在等待结束；另起一行输入英文 `.` 并回车。 |
| 输入密钥时看不到字 | 隐藏输入的正常行为，粘贴后回车即可。 |
| `No such file or directory` | 用 `cd ~/writing-workbench` 回项目目录；检查前面的安装是否成功。 |
| 找不到 RSIH | 用 `~/.local/bin/rsih --version` 检查，重新运行 `setup --rsih 实际路径`。 |
| `ready: false` | 查看哪一项为 false；缺密钥就补 setup，缺引擎就返回第 2 步。 |
| 401 / Unauthorized | 密钥无效或失效，执行 `setup --replace-key` 更换。 |
| 余额不足或限流 | 到 DeepSeek 开放平台检查账户，之后再试；本地原稿不会因调用失败被覆盖。 |
| 模型超时、网络报错 | 保留终端里的操作编号；按 [详细说明](RSIH.md#命令行自动化) 用相同事件编号加 `--retry` 重试，可避免重复保存版本。菜单再次提交会创建新操作，可能再次计费。 |
| 文件被外部修改 | 如果你用编辑器改了 `current.md`，先用菜单 6 记录手动修改，再继续；不要修改 `versions/` 中的历史稿。 |
| 提炼没有候选 | 没有足够依据时正常；继续记录真实修改，不要把每条临时要求都当作长期偏好。 |
| 关闭终端后网页还在但不能修改 | 网页仅查看；重新打开终端菜单即可。 |

请把错误文字提供给维护者排查，但不要发送密钥文件。不要直接公开整份调用日志，其中可能含工作材料。

## 9. 同事之间如何协作

每位同事先独立完成安装和配置，使用自己的材料与密钥。本版不包含团队账户登录、集中网页编辑或自动共享个人习惯。

团队管理员再根据 [进阶命令](CLI.md) 和 [接入说明](INTEGRATIONS.md) 配置实际审核仓库：提交候选 → 真人审核合并 → 核验发布 → 导出经验 → 实际提供给新任务的 AI。不能仅点击“准备审核包”就当成已发布。

当前版本的验收范围和待办见 [验收记录](ACCEPTANCE.md)。

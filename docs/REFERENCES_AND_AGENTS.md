# 参考资料写作与习惯迁移

## 从零到第一篇 Markdown

1. 首页选择「根据资料生成」（无资料时选择「从零起草」）。填写标题、文种和读者。
2. 一次选择多份参考资料，或拖到上传区域。等待解析完成，展开预览检查文字和提示；失败文件会单独列出，成功文件保留。
3. 填写写作要求，例如：「请根据这些资料生成一篇面向部门负责人的季度经营分析，约 1500 字。先写判断，再写证据和行动建议。标注数据出处，信息不足处注明待补充。」
4. 点击「创建并生成第一稿」。也可以要求留空，只创建档案，稍后再写。
5. 在 AI 草稿中核对内容，填写确认人后采用，再导出 Markdown。采用之前原稿不会被覆盖。
6. 后续可继续添加资料、选择哪些资料参与本轮，并输入额外要求。取消「采用后，本篇继续沿用」可让要求只影响本次；历史记录依然保留。

## 支持的输入与边界

| 格式 | 解析方式 | 需要核对 |
| --- | --- | --- |
| MD / TXT | UTF-8 原文 | 非 UTF-8 文本需先转换编码 |
| PDF | 按页提取文字；无文字页做 OCR | 表格布局、阅读顺序、混合页中的图片、图表关系 |
| PPTX | 文字、分组文本、表格、图表序列、演讲备注、嵌入图片 OCR | SmartArt、图形关系、动画、外部链接内容 |
| 旧版 PPT | 本地 LibreOffice 转成 PPTX 后解析 | 未装 LibreOffice 时，先在 PowerPoint 中另存为 PPTX |
| DOCX | 正文、表格、内嵌图片 OCR | 页眉页脚、文本框、修订、批注不作为正文 |
| PNG / JPG / JPEG / WEBP | 本地 OCR 识别文字 | 图像含义与曲线走势不能仅靠文字识别理解 |

macOS 安装项目依赖时会安装 Vision 的 Python 桥接包，使用系统自带识别能力，无需把图片发送给 OCR 云服务。其他系统可安装 Tesseract，并安装 `chi_sim` / `chi_tra` 中文语言包。没有可识别文字的文件会报错，不伪装成已读懂。

每份原文件上限 20 MB，每篇最多 30 份，PDF / PPTX 最多 100 页，解析限时 3 分钟，解析文本上限 2 MB。文本、原件和解析提示保存在本机 `references/`，取消选择不会删除原件或旧调用快照。没有执行外部链接抓取。

完整模型输入沿用 `writing-settings.json` 的 `max_context_bytes`（默认 60,000 UTF-8 字节）。这是保守预算，包含参考资料、当前正文、有效历史指令和习惯。页面展示所选资料的文字大小；超出时停止调用。可以取消本轮不需要的资料、拆分资料，或在核实模型实际容量后调整设置；系统不会悄悄截断来制造“全部读过”的假象。

## 给其他 Agent 使用写作习惯

在「写作习惯」中选择已确认规则，点击「导出选中习惯」。检查预览中的业务专有信息后：

- **Markdown**：面向其他 Agent，包含规则内容、适用范围、使用约定和开场指令。
- **JSON**：面向另一个 RSI 工作台，导入后成为候选，需逐条确认。

对话型 Agent：上传 `RSI-写作习惯.md`，或者将内容放到该智能体实际使用的自定义说明里。仅放入知识库未必每次检索到，任务里应明确要求读取。

能读取本地文件的 Agent：把文件放在工作目录，任务中指明相对路径。希望长期使用时，把「写作前读取 ./RSI-写作习惯.md 并按任务范围匹配规则」加入它实际加载的项目说明中，保留原项目约定。

可直接复制：

```text
请先完整读取附件 RSI-写作习惯.md。
本文文种是【经营分析】，读者是【部门负责人】，主题是【季度经营】。
先列出匹配的规则编号，再根据参考资料生成 Markdown 文稿。
本次额外要求是【填写】，与习惯冲突时以本次要求为准。
信息不足请标注待补充，不要编造事实。
```

核对两个点：Agent 本次是否读取并列出了正确规则；实际正文是否遵守。文件是静态快照，原工作台更新或撤销习惯后，要重新导出替换。导出不等于自动安装、加载或训练其他模型。

## 为什么这样实现

过去只有「原稿」字段，上传内容会直接变成待修改正文，缺少多个来源的身份与解析过程。现在把来源和输出分开：原件 → 解析文字与提示 → 本轮选择 → 调用快照 → 待采用草稿。即使以后追加或取消资料，也能看到旧稿当时依据了哪些文件。

每次生成保存资料原件指纹、解析文字指纹、文件名、页码或页序，与原始要求及适用规则一起进入不可悄悄修改的调用快照。指纹用来发现内容变化，不保证原资料事实正确。

解析放在独立子进程中，并设置文件、页数和时间上限，避免损坏文件或长时间 OCR 卡住整个网页服务。上传接口沿用本机令牌和来源校验。资料中的命令只作为内容，不授权 Agent 执行。

OCR 使用 [Apple Vision 文字识别](https://developer.apple.com/documentation/vision/vnrecognizetextrequest)，PDF 文本与页面渲染参考 [pypdfium2 官方 API](https://pypdfium2.readthedocs.io/en/stable/python_api.html)，幻灯片备注使用 [python-pptx 官方接口](https://python-pptx.readthedocs.io/en/latest/user/notes.html)。
